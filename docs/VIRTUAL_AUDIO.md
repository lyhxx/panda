# 虚拟声卡路由

## 为什么需要它

变声器只完成一半工作：把麦克风的声音换成目标音色。另一半是让**别的软件**
听到这个结果。Discord、游戏、OBS 都只从"麦克风"里取声音，所以必须有一块
虚拟声卡充当桥梁：

```text
真实麦克风 ──► Panda（变声） ──► 虚拟声卡写入端
                                       │
                                       ▼
                              虚拟声卡采集端 ──► Discord / 游戏 / OBS
```

虚拟声卡是一对设备：一个**可写入**的播放端，和一个**可读取**的采集端。
Panda 往播放端写，其它软件从采集端读。选错任何一端都不会有声音。

## 第一版的做法：依赖用户自装的虚拟声卡

Panda v1 **不自带驱动**。原因是内核音频驱动需要管理员权限安装，还需要
代码签名才能在没有警告的情况下分发，这会把"下载即用"变成"先过一遍安全
警告"。第一版选择依赖用户自行安装的虚拟声卡：

| 方案 | 说明 |
| --- | --- |
| VB-CABLE | 免费（捐赠制），只有一对设备，最简单 |
| VoiceMeeter | 免费，功能更多，虚拟设备也更多 |

这些软件安装时需要一次管理员权限，装完之后 Panda 和普通应用一样是
用户级程序。

自带签名驱动是后续工作，见本文末尾。

## 配置步骤

### 1. 安装虚拟声卡

桌面端在找不到虚拟声卡时，「输出」下拉框下面会直接给出
**去 www.vb-cable.com 下载** 按钮，点开就是官网，不用自己去搜。

安装按三步走，顺序错了安装器会报 `LOADDRV: The path does not exist`
（-106）：**解压 → 右键以管理员身份运行 → 重启**。

安装 VB-CABLE 并重启音频服务（或重启电脑）。安装后会多出两个设备：

```text
CABLE Input  (VB-Audio Virtual Cable)    <- 播放端，Panda 写这里
CABLE Output (VB-Audio Virtual Cable)    <- 采集端，其它软件读这里
```

### 2. 确认路由可用

```powershell
panda route-check --python <安装了 sounddevice 的 python>
```

有可用路由时会直接给出两端该选哪个设备：

```text
[OK] 检测到 1 条可用路由。
  路由 1:
    Panda 的输出设备 → #3 CABLE Input (VB-Audio Virtual Cable) · Windows WASAPI
    其它软件的麦克风   → #5 CABLE Output (VB-Audio Virtual Cable) · Windows WASAPI
```

没有可用路由时返回退出码 1，并说明缺什么。桌面端不调用它，这条路只留在终端里。

### 3. 在 Panda 里选输出设备

打开桌面端，在"输出设备"里选择 `CABLE Input`。装了虚拟声卡时，它在下拉框里
带 **（虚拟声卡）** 标记，认标记即可，不需要再跑一遍检查。这台机器上一个
虚拟声卡都没有时，下拉框下方会有一行说明：其它软件听不到，装 VB-CABLE 后
才能选。

### 4. 在其它软件里选麦克风

在 Discord、游戏或 OBS 的音频设置里，把麦克风选成 `CABLE Output`。

### 5.（可选）给自己加一路监听

变声结果写进虚拟声卡之后，你自己是听不到的。在 Panda 的"监听输出"里
选一个普通扬声器或耳机，变声结果会**同时**播给它：

```text
真实麦克风 ──► Panda ──┬──► CABLE Input   （其它软件从这里读）
                          └──► 你的耳机        （你自己听）
```

监听是独立的一路，走自己的缓冲，不会从主输出抢采样，也不会影响转换时序。
选"不监听"即可关闭。

## 当前限制

- **采样率要一致**。Panda 目前按 16 kHz 处理，如果虚拟声卡被设成
  44.1 kHz 且驱动不做重采样，可能出现变调或杂音。
- **虚拟声卡不提供降噪**。换声不等于去噪，噪声会被一起转换。
- **监听会引入一点额外延迟**。监听输出有自己的预滚，和主输出不完全同步。

## 排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 安装器报 `LOADDRV: The path does not exist`（-106） | 没用管理员身份运行，或在压缩包预览里直接双击了 exe，驱动 `.sys` 不在旁边 | 解压到普通文件夹，右键 `VBCABLE_Setup_x64.exe` → **以管理员身份运行** |
| 用管理员装完，设备列表里还是没有 | 官网要求 `Reboot after installation`，不重启端点不出现 | 重启电脑，再在输出下拉框旁点**刷新** |
| `route-check` 报没有可用路由 | 只装了采集端，或者虚拟声卡没装 | 安装 VB-CABLE 后重跑 |
| `route-check` 列出了 `CABLE Output` 但选不到它作为输出 | 那是采集端，不能写入 | 输出要选 `CABLE Input` |
| 对方完全听不到 | 其它软件的麦克风没改成 `CABLE Output` | 在该软件里改麦克风 |
| 声音正常但自己是聋的 | 输出独占给了虚拟声卡 | 在"监听输出"里选自己的耳机 |
| 变了调或者有杂音 | 采样率不一致 | 把虚拟声卡和设备都设成 16 kHz |

## 后续：自带签名驱动

如果将来要做得和商业软件一样"装完就能用"，需要提供一个签名过的虚拟音频
驱动，让 Panda 自己创建播放端和采集端。这条路的成本是：

- 内核模式驱动开发与测试；
- EV 代码签名证书，以及微软的驱动签名流程；
- 安装时需要一次管理员权限。

在解决这些之前，`route-check` 这条依赖用户自装虚拟声卡的路径是首发的方案。
